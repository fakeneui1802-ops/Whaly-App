# Flipper Zero capability list — audit

Verdict: **good inventory, bad spec.**

It is a solid menu of everything the Flipper ecosystem can do. It is not usable as a build
plan, because it mixes three completely different hardware situations into one list and
never says which is which:

1. **Runs on a stock phone.** NFC, IR (if an emitter exists), BLE, audio, torch, HCE.
2. **Runs on a phone plus a USB-OTG dongle.** Sub-GHz, LF RFID, iButton, SWD, real GPIO.
3. **Runs only on Flipper silicon.** The CC1101 radio, the 125 kHz analog front end, the
   ST25R3916 in card-emulation mode, the pogo-pin iButton pad.

Read as one list, it implies a phone can do all of it. It cannot.

---

## Factual errors

| Claim | Reality |
|---|---|
| Rolling code capture & replay | A rolling code cannot be replayed by definition. What actually works is capturing a frame and brute-forcing the counter inside the receiver's acceptance window (KeeLoq), which is protocol-specific and often 16-64 tries. The list should say that. |
| Chamberlain / LiftMaster Security+ 1.0 **and 2.0** | Security+ 2.0 is not broken. Only 1.0 has published weaknesses, and even those need the wall-panel seed. Listing 2.0 alongside 1.0 is wrong. |
| Faac SLH, Hormann BiSecur | AES-based rolling code. Not emulatable, not brute-forceable. |
| Marantec, Sommer, Star Line, Scher-Khan | Mixed. Some models fixed-code, some rolling. A flat entry hides that. |
| NFC Nested / Darkside attack | **Not possible from Android.** Both need control over the 7-bit frame parity, and `NfcA.transceive` sends whole bytes with parity generated by the controller. Mfkey32 works, nested and darkside do not. |
| NFC Magic Gen1A support | Gen1A unlock needs a 0x40/0x43 command in a 7-bit frame with bad parity. Same blocker as above. Gen2/CUID and Gen4/GDM work fine through normal commands. |
| Amiibo emulation (NTAG215) | Android HCE can only present an **ISO-DEP (14443-4)** card. NTAG215 is Type-2, so it cannot be emulated from a phone. Needs a PN532 or Chameleon. |
| EMV transaction log read | The log lives in the secure element and is only readable after issuer authentication. Contactless gives you PAN, expiry, ATC and the track-2 equivalent. No log. |
| BadUSB with custom VID / PID | USB gadget descriptors come from the kernel. An app cannot set them without root. BLE HID is public API and works fine; USB HID from a phone needs root. |
| U2F over USB | A phone is a USB device, not a host, and cannot present itself as a U2F token without gadget control. U2F/CTAP over **NFC** via HCE works. |
| IR learn / RAW capture | Almost no phone has an IR **receiver**. Transmit is common; receive needs an external TSOP. The list implies both are phone features. |

## Accurate and worth keeping

- Sub-GHz protocol list is largely correct for fixed-code families: Princeton, Came, Nice
  FLO, GateTX, Holtek, Ansonic, Clemsa, Dooya, Elplast, Phoenix V2, Power Smart, GangQi,
  Hollarm, Revers RB2, Feron, Legrand, Intertechno V3, SMC5326, PT2262/EV1527/HX2262.
- Weather station and TPMS decoding is real, and genuinely useful.
- 125 kHz protocol list is correct: EM4100, HID Prox, Indala, IoProx, AWID, Viking, Pyramid,
  Keri, Jablotron, Paradox, PAC/Stanley, Gallagher, Nexwatch, Noralsy, Idteck, GProxII,
  SecuraKey, Visa2000, Electra, FDX-A/B.
- IR protocol list is correct, and the timings in Whaly's encoders match it.
- Hardware specifications are all correct: STM32WB55RG (M4 64 MHz + M0+ 32 MHz), 1 MB flash,
  256 KB SRAM, CC1101, ST25R3916, TSOP75338, 2100 mAh, 128x64 reflective LCD.
- The FAP/JS/RPC section is accurate and not relevant to a phone build.

## What the list is missing

- **Proxmark3 over USB-OTG** — the single most important omission. It covers LF, HF, iButton
  and raw ISO14443 in one dongle, and it is the only realistic path to the LF half of this
  list from a phone.
- **USB-UART bridges** (FT232H, CH347, CP2102) — this is how SPI, I2C, UART and SWD actually
  reach a phone.
- **NFC relay** — not possible with one phone, worth stating so nobody plans around it.
- **DESFire EV3** — UID only without keys. The list implies more.
- **Sub-GHz RSSI/spectrum** needs the CC1101; a phone has no radio in that band at all.

## Corrected grouping

### Stock phone, no extra hardware

NFC read/write/emulate (ISO-DEP), HCE card emulation, NDEF parse/create, MIFARE Classic
dictionary and mfkey32, Ultralight/NTAG read-write, ISO15693 read, FeliCa read, EMV public
data, IR transmit, BLE HID, BLE scan and beacon, BLE spam, audio, torch, USB host to a
Proxmark or bridge.

### Phone plus one USB-OTG dongle

Sub-GHz read/emulate/brute (CC1101 bridge), 125 kHz read/write/emulate (Proxmark3), iButton
(Proxmark3 or DS9490R), SWD/JTAG (CMSIS-DAP), SPI/I2C/UART (FT232H/CH347), IR receive
(TSOP on a bridge), U2F over USB (needs gadget control, so root).

### Flipper-only silicon

Anything that requires the phone to *be* the card at 125 kHz, to hold a rolling-code counter
in hardware, or to present a Type-2 tag. Those need a PN532, Chameleon or the Flipper itself.
